# OmniMD 开发调试指南（新手向）

> 本文档面向不熟悉本项目、也不太懂开发工具链的同学。
> 按顺序读完，就能把项目跑起来、改代码、查问题。

---

## 0. 这是什么项目？

OmniMD 是一个**桌面应用**，用 **Tauri 2** 框架开发：

- **后端**用 **Rust** 语言写（`src/` 目录），负责把 PDF/Word/HTML 等文件转成 Markdown。
- **前端**用 **React + TypeScript** 写（`frontend/` 目录），是用户看到的界面。
- 打包出来就是一个 `.exe` 桌面程序，双击就能用。

### 目录结构速览

```
OmniMD/
├── src/                # Rust 后端代码
│   ├── main.rs         # 程序入口
│   ├── lib.rs          # Tauri 命令注册（前端调用的接口都在这里）
│   ├── pipeline.rs     # 转换流程（读文件→转换→写文件）
│   ├── file_utils.rs   # 文件路径工具
│   ├── converters/     # 具体转换器（用 anydoc 库）
│   └── models/         # 数据结构定义
├── frontend/           # React 前端代码
│   ├── src/
│   │   ├── App.tsx     # 应用主界面
│   │   ├── pages/      # 各个页面（首页/转换/批量）
│   │   ├── api/        # 调用 Rust 后端的桥接代码
│   │   └── store/      # 状态管理（zustand）
│   ├── package.json    # 前端依赖和命令
│   └── vite.config.ts # 前端构建配置
├── Cargo.toml          # Rust 依赖配置
├── tauri.conf.json     # Tauri 应用配置（窗口大小、打包等）
├── capabilities/       # Tauri 权限配置
└── tests/              # Rust 测试代码
```

### 前端怎么跟后端通信？

前端通过 `invoke("命令名", { 参数 })` 调用 Rust 后端函数。接口定义在 `src/lib.rs`：

| Rust 函数 | 前端调用名 | 作用 |
|-----------|-----------|------|
| `convert_file` | `convert_file` | 转换单个文件 |
| `convert_batch` | `convert_batch` | 批量转换 |
| `get_supported_formats` | `get_supported_formats` | 查询支持的格式 |
| `get_converter_info` | `get_converter_info` | 查询转换器信息 |

前端封装在 `frontend/src/api/tauriApi.ts` 里，改接口时两边都要对应。

## 1. 准备开发环境

### 1.1 需要安装的东西

| 工具 | 作用 | 检查命令 | 安装方式 |
|------|------|---------|---------|
| **Node.js** | 跑前端 | `node --version` | https://nodejs.org （选 LTS 版） |
| **pnpm** | 前端包管理器 | `pnpm --version` | 装完 Node 后运行 `npm install -g pnpm` |
| **Rust** | 编译后端 | `rustc --version` | 见下方说明 ⚠️ |
| **Microsoft C++ Build Tools** | Rust 在 Windows 上编译需要 | — | 见下方说明 ⚠️ |

### 1.2 安装 Rust（关键步骤）

> ⚠️ 目前这台机器上 Rust 还没装，必须先装才能跑后端。

1. 下载 `rustup-init.exe`：https://www.rust-lang.org/tools/install
2. 双击运行，按提示选默认安装（按回车即可）。
3. 装完后**重新打开终端**，运行 `rustc --version` 确认安装成功。

### 1.3 安装 Microsoft C++ Build Tools（Windows 必须）

Rust 在 Windows 上编译成 `.exe` 需要微软的 C++ 链接器：

1. 下载：https://visualstudio.microsoft.com/visual-cpp-build-tools/
2. 安装时勾选 **"使用 C++ 的桌面开发"** 工作负载。
3. 装完重启电脑。

### 1.4 安装 Tauri CLI（在项目根目录运行）

```powershell
cd D:\project\OmniMD
pnpm install
```

之后用 `pnpm tauri <命令>` 调用。

### 1.5 一次性确认所有工具就绪

新开一个终端，依次运行，都能出版本号就 OK：

```powershell
node --version
pnpm --version
rustc --version
cargo --version
```

## 2. 第一次运行项目

### 2.1 安装依赖（根目录 + frontend 目录）

```powershell
cd D:\project\OmniMD
pnpm install

cd D:\project\OmniMD\frontend
pnpm install
```

这一步会下载 React、Vite 等前端依赖，需要联网，等几分钟。

### 2.2 启动开发模式（边改边看效果）

**方式 A：用 Tauri CLI（推荐，一条命令搞定）**

```powershell
cd D:\project\OmniMD
pnpm tauri dev
```

这条命令会同时：
1. 启动前端开发服务器（Vite，端口 1420）。
2. 编译 Rust 后端并弹出一个桌面窗口。

> 第一次运行会编译大量 Rust 代码，可能要等 5~15 分钟，之后增量编译会快很多。

**方式 B：只看前端界面（不调 Rust 后端）**

如果只想调界面样式、不涉及文件转换功能，可以单独跑前端：

```powershell
cd D:\project\OmniMD\frontend
pnpm dev
```

然后在浏览器打开 http://localhost:1420 。注意：这种模式下点"转换"按钮会报错，因为没有 Rust 后端。

### 2.3 验证成功

- 桌面弹出窗口，标题是 "OmniMD - Anything to Markdown"。
- 左侧有 Home / Convert / Batch / Settings 导航。
- 能在 Convert 页面选文件并转换，生成 `.md` 文件。

## 3. 开发工作流（改代码怎么看效果）

### 3.1 前端代码（React/TypeScript）

- 用 `pnpm tauri dev` 启动后，**改前端代码会自动热更新**，保存文件就能在窗口里看到变化，无需重启。
- 前端代码在 `frontend/src/`，主要看 `pages/` 下的页面和 `App.tsx`。

### 3.2 后端代码（Rust）

- 改了 `src/` 下的 Rust 代码后，**需要重新编译**。如果用的是 `pnpm tauri dev`，它会自动检测到变化并重新编译，窗口会自动刷新。
- Rust 编译较慢，改完后等一会儿。

### 3.3 改完配置要重启

如果改了 `tauri.conf.json`、`Cargo.toml`、`vite.config.ts` 这些配置文件，停掉（Ctrl+C）再重新 `pnpm tauri dev`。

## 4. 日志和调试

### 4.1 看后端日志

Rust 代码里用了 `tracing` 日志库，关键位置有 `info!(...)` 输出。日志会打印在**运行 `pnpm tauri dev` 的那个终端窗口里**。例如 `lib.rs:119`：

```rust
info!("convert_file: {} -> {}", source_path, output_dir);
```

调试时多看终端输出，转换出错时这里会有报错信息。

### 4.2 看前端控制台

- 用 `pnpm dev` 在浏览器打开时，按 **F12** 打开开发者工具看 Console。
- 用 Tauri 桌面窗口时，可以按 **F12** 或 **Ctrl+Shift+I** 打开 DevTools（开发模式下默认开启）。

### 4.3 前后端调用断点

- 前端发起调用的地方在 `frontend/src/api/tauriApi.ts`，在这里加 `console.log` 能看到传给后端的参数。
- 后端接收的地方在 `src/lib.rs` 的 `#[tauri::command]` 函数，加 `info!(...)` 或 `println!(...)` 能看到收到的参数。

## 7. 常见问题

### Q1: `pnpm tauri dev` 报错 "linker 'link.exe' not found"

没装 Microsoft C++ Build Tools，回头做第 1.3 节。

### Q1.5: `pnpm tauri dev` 报错 "Couldn't recognize the current folder as a Tauri project"

确认在**项目根目录**（`D:\project\OmniMD`）运行 `pnpm tauri dev`，而不是在 `frontend/`。

### Q1.6: `pnpm tauri dev` 卡死在 "Waiting for your frontend dev server to start"

`tauri.conf.json` 中的 `build.beforeDevCommand` 已配置为 `"pnpm dev"`，会自动在项目根目录启动 Vite 开发服务器（执行 root `package.json` 的 `dev` 脚本即 `cd frontend && pnpm dev`）。首次运行会编译大量 Rust 依赖，可能需要 5~15 分钟，期间 CLI 会持续显示 "Waiting..." — 属正常现象，不是卡死。确认在**项目根目录**运行 `pnpm tauri dev`，而不是在 `frontend/`。

### Q2: 端口 1420 被占用

关掉其他占用 1420 端口的程序，或重启电脑。端口在 `vite.config.ts:9` 和 `tauri.conf.json:7` 配置，两边必须一致。

### Q3: 前端改了不生效

确认是 `pnpm tauri dev` 模式（不是 `pnpm dev`）。Tauri 桌面窗口里按 Ctrl+Shift+R 强制刷新。

### Q4: Rust 编译特别慢

第一次编译正常，之后会快。如果一直慢，检查是不是在机械硬盘上。可以在 `Cargo.toml` 同级目录的 `.cargo/config.toml` 里配置 `target` 目录到 SSD。

### Q5: 点转换按钮没反应

- 确认用的是 `pnpm tauri dev`（带后端），不是单独 `pnpm dev`。
- 看 F12 控制台有没有报错。
- 看终端有没有 Rust 的报错日志。

### Q6: `cargo` / `rustc` 命令找不到

Rust 装完后要**重新打开终端**，让环境变量生效。还不行就重启电脑。
